# Carve Full Functionality and Architecture Audit — 2026-06-26

## Executive result

No reproducible P0 issue was found. The audit found and fixed multiple P1
durability, deployment, security, and test-integrity defects. The most important
functional change is retry-safe review: first-party clients now create a stable
event UUID, the database enforces per-user uniqueness, and a replay returns the
original stored scheduling result without scheduling the card twice. Offline
storage failure is visible and blocks the review instead of silently losing it.

The repository now has one frozen pnpm workspace, blocking lint/type/build/test/
audit gates, an explicit Cloudflare-compatible static build, exact route/OpenAPI
parity, authenticated contract fuzz configuration, isolated real-stack proof,
real Chrome and Firefox package execution, a four-project web/mobile browser
matrix, and honest flow documentation.

A second proof pass expanded the isolated stack from one smoke journey to seven
complete journeys and exposed additional functional defects hidden by passing
unit tests: refresh/logout revocation, internal-only media URLs, permanent bury,
ignored daily limits, incomplete undo snapshots, empty starter subscriptions,
invalid Yomitan/JPDB persistence, ignored server-side vocabulary, a broken
Chinese WASM build, unenforced email verification, media-less APKG round trips,
multi-user deck-copy contamination, and malformed-input 500s. Each bounded
defect was fixed and exercised through the real API/browser stack.

The baseline is materially stronger but not “fully covered.” Aggregate coverage
of several large legacy Go handler packages remains 30–57%, a diagnostic broad
web mutation run scored 9.43%, Safari has no native wrapper, and some end-to-end
UI mutations/import round trips remain partial. Those are recorded below rather
than being converted into synthetic passes.

## Scope and method

The audit covered the repository, migrations, Docker Compose and phase-one
deployment configuration, Go API/media services, Python NLP service, Rust/WASM,
SvelteKit PWA, Chrome/Firefox/Safari extension bundles, mock and real-stack E2E,
CI/scheduled workflows, OpenAPI, performance scripts, and provider canaries.
Production was not modified. Real-stack tests used isolated ports, databases,
volumes, Mailpit, and non-destructive provider calls.

Statuses are `fixed`, `partial`, `open`, or `failed`. A fix is only marked
`fixed` when a regression check exists. Live-provider results use only
`passed`, `failed`, or `inconclusive`.

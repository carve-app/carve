# Deploy runbook

Solo/demo AWS deploy. Numbers in parentheses are estimated wall-clock minutes.

## One-time bootstrap (~90 min total)

### 0. Pre-reqs (15 min)
- AWS account with admin access; create an IAM user `carve-admin`, store credentials in `~/.aws/credentials` under profile `carve-admin`
- Cloudflare account with `carve.app` added (nameservers pointed at CF)
- Terraform ≥ 1.6 and AWS CLI v2 installed locally
- Docker installed (for local image builds during debugging only — CI does prod builds)

### 1. Cloudflare API token (5 min)
Dashboard → My Profile → API Tokens → Create Token. Permissions:
- `Zone:DNS:Edit` on `carve.app`
- `Account:Workers R2 Storage:Edit`
- `Account:Cloudflare Pages:Edit`

Export it locally:
```sh
export CLOUDFLARE_API_TOKEN='cf_...'
export AWS_PROFILE=carve-admin
```

Grab the Cloudflare Account ID and Zone ID from any zone's Overview page.

### 2. Bootstrap Terraform state (3 min)
```sh
cd infra/terraform/bootstrap
terraform init
terraform apply
```
Copy the `backend_hcl` output into `../backend.hcl`.

### 3. Apply main stack (~30 min — RDS creation is the long pole)
```sh
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars
$EDITOR terraform.tfvars   # paste Cloudflare account_id + zone_id

terraform init -backend-config=backend.hcl
terraform apply
```
This creates ~50 resources. RDS takes ~15 min. ACM cert is DNS-validated automatically via Cloudflare.

### 4. Capture outputs for GitHub Actions (5 min)
```sh
terraform output github_deploy_role_arn   # set as repo secret AWS_DEPLOY_ROLE_ARN
terraform output -raw github_deploy_role_arn   # same value, paste-friendly
```

Add the following to **GitHub repo → Settings → Secrets and variables → Actions**:

| Secret | Value source |
|---|---|
| `AWS_DEPLOY_ROLE_ARN` | `terraform output github_deploy_role_arn` |
| `AWS_TF_ROLE_ARN` | Same as above (for now — split later if you separate apply from deploy) |
| `CLOUDFLARE_API_TOKEN` | The token from step 1 |
| `CLOUDFLARE_ACCOUNT_ID` | From `terraform.tfvars` |
| `CLOUDFLARE_ZONE_ID` | From `terraform.tfvars` |

Also create a **GitHub environment** named `prod`. Add the same secrets there if you want approval gates on deploys.

### 5. Rotate placeholder secrets (10 min)
TF created SSM placeholders with the value `PLACEHOLDER_SET_VIA_CLI`. Real values must be in place before the first deploy goes live. See `docs/deploy/api-keys.md` for what each one is for.

Minimum to ship the first deploy successfully (everything else can be added later):
```sh
# JWT and NLP secret are auto-generated by TF — already set
# DATABASE_URL and REDIS_URL — already set by TF

# R2 credentials (create token in Cloudflare R2 → Manage R2 API Tokens)
aws ssm put-parameter --name /carve/prod/R2_ACCESS_KEY_ID     --value '...' --overwrite --type SecureString
aws ssm put-parameter --name /carve/prod/R2_SECRET_ACCESS_KEY --value '...' --overwrite --type SecureString
```

The rest (Stripe, DeepL, Forvo, OpenAI, etc.) can stay as placeholders until those features are wired.

### 6. Manual Cloudflare steps (~10 min)
The Terraform provider doesn't cover these yet:

1. **R2 custom domain**: Cloudflare → R2 → `carve-prod-media` bucket → Settings → Custom Domains → Connect `media.carve.app`.  Replaces the ALB-routed CNAME for media reads.
2. **Cloudflare Pages project**: Cloudflare → Pages → Create with GitHub → select `carve-app/carve` → set production branch to `main`, build dir `apps/web`, build cmd `npm run build`, output `apps/web/build`. The GH Action will push subsequent deploys.

### 7. SES production access (asynchronous — request takes 24h)
SES console → "Request production access". Include URL `https://carve.app`, expected volume, and use cases (transactional). Until granted, mail only goes to verified addresses.

### 8. Trigger first deploy (5 min)
Push any change under `services/`, or run from the Actions tab → **Deploy** → workflow_dispatch with `service: all`. The workflow:
1. Builds + pushes images to ECR (parallel per service)
2. Runs a one-off ECS task that executes `./migrate` against RDS
3. Force-redeploys each service to pull the new image
4. Waits for `services-stable` before marking the job green

Open `https://api.carve.app/health` — should return `{"status":"ok","service":"api"}`.

## Day-2 operations

### Push a code change
Normal git workflow. Merging to `main` triggers `.github/workflows/deploy.yml`. Only services with file changes get rebuilt + redeployed (see `detect-changes` job).

### Run a migration without a code change
Actions → Deploy → workflow_dispatch with `service: api`. The pipeline rebuilds the api image (which contains the migrations) and runs the migration task before rolling the api service.

### Rotate a secret
```sh
aws ssm put-parameter --name /carve/prod/<KEY> --value '<new>' --overwrite --type SecureString
aws ecs update-service --cluster carve-prod-cluster --service api --force-new-deployment
```
ECS pulls SSM values at task start, so a force-deploy is required for the change to take effect.

### Tail logs
```sh
aws logs tail /ecs/carve-prod/api   --follow --since 5m
aws logs tail /ecs/carve-prod/nlp   --follow --since 5m
aws logs tail /ecs/carve-prod/media --follow --since 5m
```

### Connect to RDS
RDS is in private subnets; tunnel via an ECS task or local SSM session:
```sh
# Get the endpoint
aws ssm get-parameter --name /carve/prod/DATABASE_URL --with-decryption --query Parameter.Value --output text
```
For ongoing access, run a one-off ECS task with `psql` and EXEC into it via `aws ecs execute-command` (requires `enable_execute_command = true` on the service — not enabled by default; add when needed).

### Scale up
Bump `ecs_desired_count`, `ecs_task_cpu`, `ecs_task_memory`, `rds_instance_class`, `redis_node_type` in `terraform.tfvars` and `terraform apply`. For HA Postgres past ~1k MAU, set `multi_az = true` on the RDS instance.

### Disaster recovery
- **RDS**: 7-day automated backups + PITR. Restore via `aws rds restore-db-instance-to-point-in-time`.
- **R2**: enable object versioning in the Cloudflare dashboard (one-click). Until then, R2 has no built-in undelete.
- **Terraform state**: S3 bucket has versioning enabled — recover via `aws s3api list-object-versions` on the state bucket.

## Cost guard rails

Current sizing is ~$25–40/mo. The fastest ways to blow that up:

- **Container Insights** ($1.50/cluster + $0.30/container/day). Off by default. Don't flip it on until past 1k MAU.
- **NAT gateway** ($32/mo). Skipped here — tasks have public IPs in public subnets, locked down by SGs. Adding a NAT gateway makes the network "correct" but costs more than the ALB.
- **CloudWatch logs retention** is 14 days. Each log group bills storage; if you bump retention to 90d, watch the bill.
- **Cloudflare R2 egress is $0**, but R2 storage is $0.015/GB/mo. At 100 GB you're paying $1.50/mo. Don't worry about it until ~1 TB.
- **Stripe processing fee** is the single biggest line at any non-trivial paid-user count. Negotiate down past $400k ARR.

## Decommission

```sh
cd infra/terraform
terraform destroy
# Manually delete: ECR images (TF only deletes empty repos), R2 objects,
# Cloudflare Pages project, SES domain verification.
```

The bootstrap stack (state bucket + lock table) must be destroyed separately and only after the main stack is gone:
```sh
cd infra/terraform/bootstrap
terraform destroy
```
